# Accessibility and responsive interaction notes

- The board is exposed as a labeled table with row/column counts and textual per-cell state (correct position, present elsewhere, absent, filled, or empty). A polite, atomic screen-reader-only region announces accepted guesses, meaningful outcomes, invalid guesses, and timeouts without reading every timer tick.
- The on-screen keyboard uses real buttons with stateful accessible names and native disabled behavior. Physical input accepts A–Z, Enter, and Backspace; repeated Enter and events originating from interactive controls are ignored by the global handler. Multiplayer submissions lock input until acknowledgement (or an eight-second visible retry error), preventing duplicate network actions.
- Dialogs focus their close control, trap Tab navigation, support Escape, and restore the opener's focus. Inputs have labels; errors use alert/status semantics and room-code entry submits with Enter.
- The default restrained palette is preserved, with small darkening adjustments to green/gray and dark text on yellow tiles to improve contrast. The focus ring uses the accessible dark green token in both themes. Reduced-motion media preferences suppress tile and control motion; timers use the deadline and refresh immediately when a background tab becomes visible.
- Layout rules cover 320px minimum width, 430px/760px breakpoints, safe-area padding, 44px-tall keyboard keys, modal scrolling, and narrow leaderboard/stat layouts. Browser smoke testing confirmed the help dialog's focus/escape/restore behavior and physical keyboard entry. Automated UI tests are component/server tests plus static responsive/contrast contracts; a full assistive-technology and device matrix still requires manual QA.
